# core — ядро модели деталей

Дерево модулей (JSON) → модель деталей → проверки → смета, раскрой, файлы, 3D/AR.
Модель деталей строится только здесь, на сервере; приложение и ссылка клиента её только показывают.

## Запуск

```bash
cd core
uv sync
uv run pytest                                   # 93 теста
uv run mebel build tests/fixtures/wardrobe_full.json --svg ../out/w.svg --svg-inside ../out/w_in.svg --glb ../out/w.glb
uv run python scripts/dump_schema.py            # схема → /schemas/product.schema.json
```

Если изменение модуля или правила меняет детали, тест эталонов упадёт. Если изменение задумано:
`UPDATE_GOLDEN=1 uv run pytest tests/test_golden.py` — и показать разницу конструктору.

## Что умеет

**Шкафы** (`type: "wardrobe"`): корпус (крыша между боковинами или накладная, цоколь, карниз, ХДФ сзади — делится по перегородкам, если не помещается на лист), секции, антресоль, зоны по высоте (полки, штанга, ящики внутренние и с фасадами, пустые), распашные двери, двери-купе с зеркалами, торцевые радиусные секции слева и справа.

**Кухня** (`type: "kitchen"`), прямая и угловая (Г): нижние модули (двери, ящики, мойка, ниша под технику, глухой угловой с фальш-панелью) на ножках с царгами, верхние на стене (двери, открытые, над вытяжкой), столешница и цоколь — делятся по стыкам модулей, если длиннее плиты или листа. Второй ряд угловой кухни поворачивается к соседней стене; верхние второго ряда встают от угла или вплотную к фасадам первого.

**Фурнитура (FR-46)**: тип и класс петель и направляющих в дереве (`hardware`); `hardware_options` — варианты замены с разницей в цене и готовым патчем; push-петли и ручки-скобы проверяются на совместимость.

**Прайс**: смета, раскрой и заказ считаются по переданному `PriceBook` (API собирает его из каталога), по умолчанию — демо-прайс; цены старше 14 дней помечаются «устарела».

**Заказ поставщику**: `supplier_order` — состав заказа без позиций «под запрос», вес, доставка по правилам EMAN.

**Операции формы**: скругление угла, вырез, паз и четверть, выборка — по ключу детали, с правилами станка.

**Правила** (`rules.py`, значения подтверждает конструктор): пролёт полки, ширина двери, петли по высоте, проставки для ящиков за дверью, дверь у стены ниши, ширина дверей-купе, деталь больше листа (с учётом текстуры), пересечения деталей. У замечаний — готовые исправления (JSON Patch), `apply_fix` применяет.

**Присадка**: конфирматы (Ø7 в пласти + Ø5×50 в торце), полкодержатели, планки и чашки петель, направляющие, ручки — по линии 37 мм.

**Подвижные узлы**: двери (поворот), ящики (выдвижение), купе (сдвиг) — для 3D и GLB «открыто».

**Выходы**:
| Что | Функция |
| --- | --- |
| 3D-модель для приложения и ссылки | `viewer_model(result)` |
| GLB «закрыто» и «открыто», метры | `export_glb(result, opened=)` |
| Раскрой по листам (гильотинный, текстура, пропил, обрезка) | `nest(result)` |
| Смета, «от–до» до замера, три вида для клиента | `estimate`, `estimate_range`, `client_view` |
| CSV для онлайн-кроя | `export_csv` |
| DXF деталей по слоям (контур, вырезы, пазы, выборки, отверстия) | `export_dxf_zip`, `part_dxf` |
| Excel: спецификация, фурнитура, раскрой, смета мастера | `export_xlsx(with_cost=)` |
| PDF: спецификация, карты раскроя, чертежи деталей с присадкой, общий вид, схема сборки, КП (рус/ўзб) | `export_*_pdf` |
| Миграция старых деревьев, применение замера | `migrate_tree`, `apply_measurements` |

## Допущения, которые нужно подтвердить

С конструктором (в `rules.py` помечены «уточнить»): отступ полок 20 мм; зазор полки на полкодержателях 1 мм; кромка 2 / 0,4 мм; конфирматы по длине соединения; цоколь шкафа из двух планок; отступ внутреннего ящика 25 мм и проставка 16 мм; минимальная ширина секции 150 мм.

С EMAN: формат CSV онлайн-кроя; пропил 4 мм и обрезка 10 мм; вычеты профильной системы купе; правила ЧПУ (радиус фрезы, отступы); размеры листов и плит столешниц.

Демо-прайс (`pricing.py`) выдуман — до парсера прайса EMAN его нельзя показывать мастерам.
