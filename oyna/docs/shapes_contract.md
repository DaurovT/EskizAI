## 1. Форма рамы — `doc.frame.shape` + `doc.frame.shape_params`

Координаты как везде: мм от левого верхнего угла габарита рамы, y вниз. `frame.w`, `frame.h` — габарит (описанный прямоугольник).

| shape | shape_params | контур (по часовой от левого нижнего угла) | ограничения (block) |
|---|---|---|---|
| `rect` (по умолчанию, или нет поля) | — | прямоугольник | — |
| `arch` | `{rise}` мм, 50 ≤ rise ≤ min(w/2, h) | низ и бока прямые, верх — дуга окружности через (0, rise), (w/2, 0), (w, rise). rise = w/2 = h → полукруглое окно | rise вне диапазона |
| `circle` | — | окружность, w = h | w ≠ h (допуск 2 мм) |
| `trapezoid` | `{h_left, h_right}` мм, одно из них = h | верх — прямая от (0, h − h_left) до (w, h − h_right) | min(h_left, h_right) < 300 |
| `bevel` | `{corner: 'tl'│'tr'│'both', dx, dy}` мм | прямоугольник со срезанным верхним углом (углами) по катетам dx, dy | dx ≥ w/2 или dy ≥ h/2 при `both`; dx > w − 300 |
| `triangle` | `{apex}` мм, 0 ≤ apex ≤ w | вершина (apex, 0), основание — низ рамы | h < 300 |

Дерево ячеек (`frame.root`) раскладывается как обычно прямоугольниками (`layout`). Реальная форма ячейки = её прямоугольник ∩ контур рамы.
- Ячейка, которую контур обрезает, — **фигурная** (`shaped: true`). Геометрия ядра отдаёт для неё `poly` — точки контура света, дуга аппроксимируется ломаной с шагом не больше 10°.
- Импосты обрезаются контуром.
- Старая запись `root.shape = "arch"`, `root.rise_mm` (шаблон T16) читается как `frame.shape = "arch"`, `shape_params.rise = rise_mm`.

Расчёт:
- Профиль рамы по фигурной части идёт по длине контура: длина дуги или наклона. Гнутый участок `arch`/`circle` добавляет работу «гибка профиля» за метр гнутой части — роль `work_bend`.
- Стекло фигурной ячейки: площадь по `poly`, плюс `shaped_extra_pct` из `glass.csv` (уже есть, 30 %).
- Створка в фигурной ячейке:
  - разрешены `turn` и `tilt` (арка, трапеция, скос), `tilt` — у полукруга;
  - `tilt_turn`, `sliding`, `pivot` в фигурной ячейке — block 4.20 «в фигурной створке только распашное или откидное»;
  - фигурная створка добавляет позицию «спецфурнитура для фигурной створки» — роль `fit_shaped`, warn 4.21.

Решение ядра: ограничения формы из таблицы — правило **1.8** (block «Параметры формы рамы вне допустимого»), команда `set_shape` с такими параметрами отклоняется.
Решение ядра: «полукруг» = `arch` с `rise = h` (пяты на низу рамы); у полукруга, `circle` и `triangle` в фигурной ячейке можно только `tilt`; `top_hung` в фигурной ячейке — тоже 4.20.
Решение ядра: ответ геометрии — у фигурной ячейки `CellGeo.shaped: true`, `poly: [[x, y], …]` (контур света), `glass_area_m2`; у фигурной рамы `Geometry.shape`, `contour` (наружный контур), `area_m2`. `light`, `glass`, `sash` — габариты (описанный прямоугольник). Цена за м² и монтаж — по площади контура.
Решение ядра: гнутый кусок рамы длиннее хлыста делится на равные части; `work_bend` = гнутые метры рамы + створок.
Решение ядра: шаблон хранит форму полями `shape`, `shape_params` рядом с `root`; `/oyna/templates` отдаёт их так же.

## 2. Раскладка — `cell.muntins`

```json
"muntins": {"kind": "inner", "v": 2, "h": 1, "width_mm": 18, "pattern": "grid", "color": "decor"}
```
- `kind`:
  - `inner` — внутри стеклопакета; ширина 8, 18 или 26 мм; нужна камера стеклопакета ≥ 12 мм, иначе block 5.20;
  - `overlay` — накладная (фальш-переплёт) с двух сторон, ширина 18, 26 или 45 мм.
- `pattern`:
  - `grid` — `v` вертикальных и `h` горизонтальных прутков, равный шаг по свету ячейки;
  - `sun` — «солнышко» для арки: `v` лучей из центра низа дуги и `h` дуговых колец;
  - `cross` — один вертикальный и один горизонтальный пруток по центру, без параметров;
  - `decor` — декоративная (кованая) вставка, как в дверях, считается за м² стекла ячейки.
- `color`: `white` | `decor` (как ламинация стороны) | `gold`.
- Убрать раскладку: `muntins: null` или нет поля.
- Работает на любой ячейке со стеклом: fixed, sash, door_sash. У `panel` — block 5.21.

Расчёт (BOM):
- `inner` — профиль раскладки погонными метрами (роль `muntin_inner`) плюс крестовины, штуки = точки пересечения (роль `muntin_cross`);
- `overlay` — погонные метры × 2 стороны (роль `muntin_overlay`);
- `decor` — м² (роль `muntin_decor`).
- Прутки длиной меньше 150 мм дают warn 5.22 «слишком мелкая раскладка».

Решение ядра: прутки строятся по видимому стеклу ячейки (по штапику). 5.22 — по самому короткому куску прутка между пересечениями и краем. У `sun` крестовины = лучи × кольца, внутри стекла. Неверная ширина или `kind` — команда `set_muntins` отклоняется.

## 3. Новые открывания — `cell.open`

К `turn | tilt_turn | tilt | sliding` добавляются:
- `top_hung` — подвесное, петли сверху, открывается наружу (`hinge: 'top'`). Фурнитура — роль `fit_top_hung`.
- `pivot` — среднеподвесное, ось горизонтальная посередине. Фурнитура — роль `fit_pivot`. Створка не больше 1600×1600 (block 4.22).

Знаки на схеме — по ГОСТ, как на картинке владельца:
- подвесное — треугольник вершиной вверх, линии от нижних углов к середине верха;
- среднеподвесное — ромб пунктиром, вершины на серединах сторон.

Решение ядра: `set_cell` с новым `open` без `hinge`: `top_hung` → `hinge: top`, `tilt` → `bottom`, `pivot` → `hinge` убирается, `turn`/`tilt_turn` с `top`/`bottom` → `left`. Пределы створки (`rules_level1.json`, `sash_limits`): `top_hung` 400–1600 × 300–1400 мм, до 2 м²; `pivot` 500–1600 × 500–1600, до 2,56 м²; больше 1600 у `pivot` — только 4.22, без 2.2. Комплект фурнитуры — одна строка роли (`fit_top_hung` / `fit_pivot`), набор фурнитуры цеха не проверяется (7.8 не срабатывает).

## 4. Составные изделия: угловые окна, эркеры, витражи — `kind: "assembly"`

```json
{"kind": "assembly", "frame": {"w": 0, "h": 1500, "root": {"assembly": [
  {"frame": {"w": 1200, "h": 1500, "root": {...}}},
  {"joint": "angle", "angle": 135},
  {"frame": {"w": 900, "h": 1500, "shape": "rect", "root": {...}}},
  {"joint": "angle", "angle": 135},
  {"frame": {"w": 1200, "h": 1500, "root": {...}}}
]}}}
```
- Элементы чередуются: рама, стык, рама, … Рама — полноценный `frame` (`w`, `h`, `shape`, `root`). Для старых шаблонов допустима строка — id шаблона, плюс `w`.
- `joint`:
  - `straight` — соединитель 180°, роль `conn_straight`;
  - `angle` с `angle` 90…179° — угловой (90°) или эркерный соединитель, роли `conn_corner90` и `conn_bay`;
  - `post` — несущая стойка или колонна, роль `conn_post`.
- `frame.w` у сборки = сумма `w` рам (развёртка), `frame.h` = max h.
- Адресация ячеек в командах и нарушениях — префикс рамы `A<i>/`: `"A0/1.0"`, `"A2/"` (корень третьей рамы). Без префикса — обычное окно.
- Команды сборки:
  - `set_joint {index, joint, angle}`;
  - `add_frame {after, w}`;
  - `remove_frame {index}`.
  Остальные команды (`split`, `set_cell`, `set_muntins`, …) принимают путь с префиксом.
- Расчёт: каждая рама считается как отдельное окно, без монтажа. Плюс соединители: длина = высота стыка (роль соединителя). Монтаж — один на всю сборку по суммарной площади.
- Правило 9.7 «составные после MVP» снимается.
- Новые правила:
  - 9.20 — угол стыка вне 90…179° → block;
  - 9.21 — высоты соседних рам отличаются больше 5 мм → warn.

Решение ядра: длина соединителя = большая из высот соседних рам. 9.20 и 9.21 — с `path: ""`, номер стыка в `msg`. Правила комплектации (7.2, 7.10, 2.20, 5.3, 5.8) у сборки — один раз без префикса; 6.10 — только если глухие все рамы. Тип рамы для правил: есть `door_sash` → `balcony_block`, иначе `window` (можно задать `frame.kind`).
Решение ядра: геометрия сборки — `cells` и `mullions` с путями `A<i>/…` и x в развёртке, плюс `frames: [{index, x, w, h, shape, contour?}]` и `joints: [{index, joint, angle, x, length, role}]`.
Решение ядра: `set_size {path: "A1/", w?, h?}` — размер рамы; `set_size {h}` без пути — высота всех рам; ширину сборки без пути менять нельзя. `add_frame {after, w, h?}` — `after: -1` в начало, стык копируется с соседнего; `remove_frame` — не меньше двух рам. Старые стыки `"angle_90"` читаются как `{joint: "angle", angle: 90}`. `frame.w`/`h` сборки пересчитываются после каждой команды.

## 6. Шаблоны (`oyna_data/templates.json`)

Новое поле `category`:
- `window` — окна;
- `door` — двери;
- `balcony` — балконные блоки;
- `sliding` — раздвижные;
- `shaped` — фигурные;
- `muntins` — с раскладкой;
- `corner` — угловые и эркеры;
- `facade` — витражи.

Короткие имена — в `short`. Минимальный набор, всего ~45:
- **Окна:**
  - 1, 2, 3, 4 створки в разных комбинациях п/о и глухих;
  - с фрамугой (откидная сверху, глухая сверху);
  - штульп;
  - подвесное;
  - среднеподвесное;
  - узкое глухое.
- **Двери:**
  - балконная одна;
  - балконная с фрамугой;
  - входная одностворчатая (стекло; стекло и панель);
  - входная двустворчатая (неравные створки);
  - входная с фрамугой.
- **Балкон:** дверь слева или справа плюс окно; дверь по центру плюс два окна.
- **Раздвижные:** 2, 3, 4 створки (уже есть), портал.
- **Фигурные:**
  - арка глухая;
  - арка с поворотной створкой;
  - арка над двумя створками (импост под дугой);
  - лучковая (малый подъём);
  - полукруг;
  - круг;
  - трапеция левая и правая;
  - треугольник;
  - скошенный угол;
  - «дом» (bevel both).
- **С раскладкой:**
  - двухстворчатое с английской раскладкой 2×3 — как на фото владельца;
  - трёхстворчатое с раскладкой;
  - арка с «солнышком»;
  - дверь с декоративной вставкой.
- **Угловые и эркеры:**
  - угловое 90°;
  - эркер 3 грани 135°;
  - эркер 5 граней;
  - полукруглый эркер 7 граней 154°.
- **Витражи:**
  - витраж 3×2 с импостами;
  - витраж с дверью.

Решение ядра: в `templates.json` у каждого шаблона есть `category`, `short` (до 22 символов) и `ready`. `ready: false` — только раздвижные (T12–T14, портал T30): они по-прежнему 9.7. Входная «стекло + панель» в одной створке деревом не описывается — T26 сделан со створкой-панелью (`fill.kind: panel`). У изделия `kind: door` без выбранной фурнитуры берётся набор, который делает дверь (иначе 8.6). У T09/T10 размер по умолчанию 1600 × 2100 — чтобы створки входили в паспорт Akfa 6000.

## 8. Цвет профиля ≠ ламинация ≠ декор окна (уточнение владельца, 2026-11-19)

Сейчас `setup.color_out` / `color_in` смешивают три разные вещи. Разделяем:

1. **Цвет профиля (в массе)** — `setup.profile_color`:
   - ПВХ: `white` (по умолчанию), `cream` (слоновая кость), `brown` (коричневый в массе), `grey`, `anthracite`;
   - алюминий: `ral:<код>` (порошковая покраска, напр. `ral:9016`, `ral:8017`) или `anodized`;
   - влияет на цену профиля: наценка к цене белого — роль `profile_color` (% или за метр, ДЕМО: кремовый +12 %, коричневый/серый/антрацит +25 %, RAL +18 %);
   - правило 2.20: цвет в массе есть не у всех систем (`systems.colors`) → lock с вариантами.
2. **Ламинация** — `setup.lam_out`, `setup.lam_in`: id плёнки из `decors.json` (`golden_oak`, `mahogany`, `walnut`, `anthracite`, …) или `null` (нет):
   - одна сторона, обе стороны — независимо;
   - расчёт: погонные метры профиля × сторона, роль `lamination` (ДЕМО 18 000 сум/м за сторону);
   - для алюминия ламинация = «под дерево» (сублимация), та же роль.
3. **Декор окна** — украшения, отдельно от цвета:
   - раскладка (`cell.muntins`, §2);
   - декоративное стекло — `cell.fill.decor`: `matte` (матовое), `tinted` (тонированное, + `tint`: bronze|grey|blue), `mirror`, `pattern` (узорчатое), `stained` (витраж). Роль `glass_decor` за м² (ДЕМО: матовое 80 000, тонировка 70 000, зеркальное 120 000, узорчатое 90 000, витраж 450 000);
   - накладки петель цветные — уже есть (`option:hinge_cap`).

**Видимый цвет стороны** (схема, 3D, КП) = ламинация этой стороны, иначе цвет профиля.
Функция в ядре `side_color(setup, side)` и в приложении `profileHex(setup, side)` (`src/lib/decors.ts`).

**Совместимость:** старые `color_out` / `color_in` читаются как:
- `white` → нет ламинации;
- иначе `lam_out` / `lam_in` = значение.
Новые документы пишут только новые поля.

**Комплектация в приложении** (строка чипов в редакторе и экран «Комплектация»):
- Профиль;
- Цвет профиля;
- Ламинация снаружи;
- Ламинация внутри;
- Стекло;
- Фурнитура.

Декор стекла и раскладка — в панели ячейки. В `/alternatives` новые `what`: `profile_color`, `lam_out`, `lam_in`, `glass_decor` (с путём ячейки).
Команды:
- `set_setup` с полями `profile_color`, `lam_out`, `lam_in`;
- `set_fill` с `decor`.

Решение ядра: ламинация считается через группу прайса, если у системы она есть: у Romchi цена ламинированного профиля уже в каталоге. Тогда строки `lamination` нет. Если группы нет, профиль идёт по белому, а ламинация — строкой `lamination`: погонные метры профиля и штапика × число сторон. 7.10 в этом случае не срабатывает.
Решение ядра: `systems.colors` — это ценовые группы прайса, не цвета в массе. Какие цвета в массе есть у системы, лежит в `oyna_data/profile_colors.json` (ДЕМО, по бренду); оттуда берёт данные правило 2.20. Наценка `profile_color` (`unit: pct`) считается в % от стоимости профиля и штапика. У алюминия `ral:*` и `anodized` идут в группу «Цветной», если она есть у системы; `ral:9016` = белый.
Решение ядра: `setup` в ответе `validate`/`calc` содержит `profile_color`, `lam_out`, `lam_in` и производные `color_out`/`color_in` (= `side_color`). `set_setup` пишет только новые поля и убирает старые; старые `color_*` в команде переводятся в `lam_*`.
Решение ядра: `set_fill {path, decor, tint?}` без `fill` меняет только декор, `decor: null` убирает его. В `/alternatives` у `lam_*` и `glass_decor` есть вариант `value: null` — «нет».

## 9. Второй этап гибкости (владелец, 2026-11-19: «дорабатывай» всё из списка)

Все цены новых ролей — ДЕМО (`demo_price_sum`), реальные цех внесёт сам. Коды правил — свободные номера в своих группах, впиши их сюда.

### 9.1 Двери и порталы
- `cell.open_dir`: `in` (по умолчанию для окон и балконных) | `out` (часто для входных). Петли и фурнитура дверей зависят от направления — роль `fit_door_out`. Знак на схеме: подпись «наружу».
- `cell.threshold` для `door_sash`: `standard` (рамный) | `low_alu` (низкий алюминиевый, роль `threshold_alu`, за м) | `none`.
- Новые открывания:
  - `folding` — гармошка: узел `split: "folding"`, n створок, фурнитура `fit_folding` за створку;
  - `psk` — параллельно-сдвижная: `fit_psk` за створку, правило — вес створки ≤ 160 кг;
  - `hs` — подъёмно-сдвижная, только системы с признаком `hs` в паспорте: `fit_hs` за створку, `threshold_hs` за м, правило — система не поддерживает → lock.
- Алюминиевые входные группы и витрины — шаблоны на `alu_tr_*` и `alu_uz` (тёплый и холодный алюминий): дверь с фрамугой, витрина 3×2 с дверью, двустворчатая входная.

Решение ядра (9.1): правила — **3.20** (block, вес створки PSK больше 160 кг) и **7.20** (lock, у системы в паспорте нет `hs`; ДЕМО: `hs: true` у классов `pvc_70` и `alu_thermo`). `fit_door_out` добавляется к фурнитуре `door_sash` с `open_dir: "out"`. Порог `threshold_alu` считается по ширине створки, `threshold_hs` — по ширине ячейки. Старое `threshold: true` = `standard`.
Решение ядра (9.1): гармошка — `split {path, dir: "folding", n}`. Створки идут без импостов и без захода друг на друга, у всех `open: "folding"`, ручка у последней. Пределы створки в `sash_limits`: `folding` 300–1000 × 500–2600, `psk` 600–1800 × 600–2400 до 3,5 м², `hs` 800–3300 × 1000–3000 до 9 м². Для `folding`, `psk`, `hs` не проверяются паспорт системы, 8.1/8.2 и 3.1 (у PSK свой 3.20).
Решение ядра (9.1): шаблоны — T30 «Портал HS» (теперь считается, `ready: true`), T51 «Портал PSK», T52 «Гармошка», T53 «Алюм. дверь + фрамуга» (Termo 70 + `alu_tr_a3400`), T54 «Алюм. витрина с дверью» (Aldoks + `alu_uz`), T55 «Алюм. двустворчатая». У шаблона может быть своя `setup` (система, фурнитура, стекло) — `create_from_template` берёт её, переданная `setup` её перекрывает. У `alu_tr_a3400` появилось открывание `door`: ДЕМО-петли и замок в `fitting_rules.csv`.

### 9.2 Москитные сетки
`cell.mosquito`: `true` — читается как `frame`, или объект `{type}`. Роли за м² сетки, у дверной за штуку:

| type | что это | роль |
|---|---|---|
| `frame` | рамочная | `mosq_frame` |
| `sliding` | раздвижная | `mosq_sliding` |
| `pleated` | плиссе | `mosq_pleated` |
| `door` | дверная на петлях | `mosq_door` |
| `antipet` | «антикошка» (усиленное полотно) | `mosq_antipet` |

Плиссе и дверная — только на `door_sash` или широкий проём (warn).

Решение ядра (9.2): warn **9.22**, «широкий проём» — створка от 1200 мм. Сетка считается по габариту створки (м²), дверная — штуками. `mosquito: true` теперь даёт строку `mosq_frame`. Учтите: у цеха без ДЕМО-цен это срабатывает P.1, пока цех не внесёт цену сетки. Команда — `set_cell {path, mosquito: true | {type} | false}`.

### 9.3 Дополнительные профили
`doc.addons`: `[{type, side, size_mm?, length_mm?}]`. `side`: `top | bottom | left | right | all`; длина по умолчанию = сторона рамы.

| type | что это | роль |
|---|---|---|
| `extender` | расширитель, size 20/40/60/100 | `addon_extender` за м |
| `base_profile` | подставочный (обычно снизу) | `addon_base` за м |
| `frame_connector` | соединитель коробок | `addon_connector` за м |
| `cover_strip` | нащельник | `addon_cover` за м |
| `canopy` | козырёк, ширина в `size_mm` | `addon_canopy` за м |

Габарит изделия в чертеже и расчёте увеличивается на расширители и подставочный профиль. Правило: расширитель на стороне со створкой — warn.

Решение ядра (9.3): команда `set_addons {addons: [...]}` заменяет весь список, `[]` — убрать. У расширителя `size_mm` только 20 | 40 | 60 | 100. Подставочный профиль без `size_mm` увеличивает габарит на 30 мм (ДЕМО). Площадь для цены, монтажа и рольставни считается по увеличенному габариту. Warn — **9.23**: расширитель на стороне рамы, к которой примыкает створка. Сборке добавки задаются на уровне всей сборки.

### 9.4 Встроенное в окно
- `cell.vent`: `{type: 'supply_valve'}` — приточный клапан, роль `vent_valve` за шт. Ставится в верхний профиль створки или рамы.
- `doc.shutter`: `{type: 'roller' | 'blinds', control: 'manual' | 'electric'}` — роль `shutter_roller` / `shutter_blinds` за м², `shutter_motor` за шт. В схеме — короб сверху.
- `doc.grille`: `{type: 'fixed' | 'opening', pattern: 'straight' | 'forged'}` — роль `grille` за м².

Решение ядра (9.4): команды — `set_cell {path, vent: {type: "supply_valve"} | null}`, `set_shutter {shutter | null}`, `set_grille {grille | null}`. Рольставня, жалюзи и решётка считаются по габариту с добавками. Вариант решётки (`straight` / `forged`) — разная ДЕМО-цена.

### 9.5 Лоджия целиком
Шаблоны лоджии — `assembly`: П-образная, Г-образная, прямая. Плюс `doc.loggia`:
```json
{"outrigger_mm": 300, "roof": true, "cladding": "outside" | "inside" | "both" | null, "parapet": "brick" | "metal" | null}
```

| что | роль |
|---|---|
| вынос остекления | `loggia_outrigger`, за м по длине |
| крыша | `loggia_roof`, за м² (длина × вынос + 500 мм) |
| обшивка | `loggia_cladding`, за м² (парапет высотой 1000 мм по умолчанию) |

Тип изделия «лоджия» в мастере замера больше не «скоро».

Решение ядра (9.5): команда `set_loggia {loggia | null}`, можно добавить `parapet_h_mm` (по умолчанию 1000). Длина — `frame.w` изделия (у сборки — развёртка). `both` = обшивка с двух сторон, × 2. Вид `parapet` идёт только подписью, отдельной цены нет. Шаблоны лоджии: T15 П-образная, T56 Г-образная, T57 прямая (`loggia` в шаблоне, `category: corner`).

### 9.6 Комплектация, которую можно выбрать
- Опции (option groups, как `handle` и `hinge`):
  - `handle`: + `handle_key` (ручка с ключом), `handle_lock` (с кнопкой — детский замок);
  - `child_lock` (замок-блокиратор);
  - `micro_vent` (микропроветривание);
  - `limiter` (ограничитель открывания);
  - `comb` (гребёнка).
  Всё в `fitting_rules.csv` с `demo_price_sum`, по умолчанию «нет».
- Стекло — пресеты в `glass.csv` и чипы в своей формуле:
  - триплекс (`t`: 3.3.1 / 4.4.1);
  - аргон (`Ar`);
  - тёплая рамка (`TGI` / `warm`);
  - бронированное (`P4A`).
  Каждое добавляет наценку за м², уже есть механизм `glass_formula.json`.
- `setup.seal_color`: `black` | `grey` (наценка 0, но в спецификации разные артикулы, если есть).
- `setup.bead`: `square` | `round` | `profiled` (штапик) — артикул в спецификации, ДЕМО-наценка для фигурного.

Решение ядра (9.6): опции фурнитуры — строки `*euro_pvc` в `fitting_rules.csv`. `handle_key` и `handle_lock` входят в группу `handle` (теперь в ней 7 вариантов). Группы `child_lock`, `micro_vent` (только `tilt_turn`), `limiter`, `comb` по умолчанию пустые, выбираются через `set_option {group, code, path?}`.
Решение ядра (9.6): в формуле стекла у рамки появился суффикс `tgi` или `warm` — тёплая рамка, +25 000 за камеру. У стекла суффикс `p4a` — бронированное, +600 000 за стекло (`glass_formula.json`, ДЕМО). Пресеты: `g331_8_4` (триплекс), `g4_16ar_4i`, `g4_16artgi_4i`, `g444p4a_12_4`. Пресет теперь разбирается по колонке `formula` из `glass.csv`.
Решение ядра (9.6): серого артикула уплотнителя в каталоге нет. Поэтому `seal_color: grey` пока только подпись «(серый)» и примечание, цена как у чёрного. Для `bead: profiled` добавляется строка `bead_profiled` за метр штапика (ДЕМО 5 000).

### 9.7 Гибкость цены и работы
- **Свои шаблоны цеха.** Таблица `company_templates` (id, company_id, name, short, category, doc_json, created_by). API:
  - `GET` / `POST` / `DELETE /oyna/company/templates`;
  - в `GET /oyna/templates` свои идут первыми, `own: true`;
  - в редакторе «Ещё → Сохранить как шаблон».

  Решение ядра: `POST /oyna/company/templates {name, short?, category?, doc}` (owner, manager, measurer; категория угадывается по изделию). `GET` отдаёт список в формате `/oyna/templates` плюс `own: true`, `doc`. `DELETE /oyna/company/templates/{id}` — владелец, менеджер или автор. `POST /oyna/positions/from-template {template: <uuid>}` создаёт позицию из своего шаблона. Изделие сохраняется без `id`, `room`, `opening`, `accepted_warnings`, `qty`. Если `w`/`h` отличаются от шаблона, параметры формы масштабируются пропорционально; полукруг остаётся полукругом.
- **Своя строка в позиции.** `doc.custom_lines`: `[{name, qty, unit, price_sum, cost_sum?}]`. Входит в BOM как `kind: 'custom'`, в цену позиции — с наценкой, если не задано `no_markup: true`. В приложении — «Расчёт → Добавить строку» у позиции.

  Решение ядра: команда `set_custom_lines {lines}` заменяет весь список. Строка BOM: `kind: "custom"`, `code: "custom:<i>"`, `price_status: "price"`. Без `no_markup`: себестоимость = `qty × (cost_sum ?? price_sum)`, на неё идёт наценка. С `no_markup`: в цену клиенту идёт `qty × price_sum` без наценки, в себестоимость — `qty × (cost_sum ?? price_sum)`. Скидка позиции действует на всё.
- **Наценка по группам.** `companies.markup_groups`, напр. `{"profile": 30, "glass": 20, "fittings": 35, "works": 0, "other": 25}`, в том же `markup_kind`. Если групп нет — общая наценка, как сейчас. Группа строки BOM — по роли. Экран «Настройки → Наценка»: общий или по группам.
- **Несколько поставщиков.**
  - Таблица `suppliers` (id, company_id, name, note).
  - `item_prices` и `glass_prices` получают `supplier_id` (null = основной).
  - `company_suppliers_default`: по категории (`profile` / `glass` / `fittings` / `other`) выбран основной поставщик.
  - В позиции `setup.suppliers`: `{glass: "<id>"}` — переопределить. В расчёте строка показывает поставщика.
  - `alternatives` с `what=supplier:glass` — сравнить цены поставщиков.
- **Импорт прайса Excel** и **веб-кабинет цен** — отдельный агент (раздел 10).

## 10. Веб-кабинет цен (S14, макет `app/docs/design/CatalogWeb.dc.html`)
Сервер отдаёт кабинет сам: `https://api.oyna.eskizai.uz/cabinet`, без отдельной сборки фронта.
- Вход — SMS-кодом как в приложении. Токен в cookie (`httpOnly`, `Secure`, `SameSite=Lax`).
- Права: owner и manager.
- Разделы:
  - **Каталог и цены** — таблица позиций, фильтры по категории, системе, «без цены», «ДЕМО»; правка цены в строке; история версий цен (`price_versions`).
  - **Стекло** — цены пакетов и формула.
  - **Работы** — ставки.
  - **Поставщики** — список, основной по категориям.
  - **Импорт Excel** — загрузить xlsx или csv, сопоставить колонки (артикул, название, цена, валюта, единица), предпросмотр совпадений (по артикулу, затем по названию) → применить как новую версию цен выбранного поставщика. Есть отмена последнего импорта.
  - **Наценка** — общая или по группам.
