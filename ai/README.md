# ai — понимание фото и текста

ИИ отвечает только за понимание: что изображено и что хочет клиент. Дерево модулей
он собирает строго по схеме ядра; детали, цены и файлы считает ядро (раздел 6 PRD).

| Задача | Модель | Как |
| --- | --- | --- |
| Фото или текст → тип, элементы, дерево, вопросы | Claude Sonnet 5.5 | Структурированный вывод по схеме `DesignResponse`; проверка схемой и сборкой; до 2 повторов |
| Правка словами | Claude Haiku 5.5 → Sonnet 5.5 | JSON Patch к дереву; 2 попытки Haiku, затем Sonnet |

- Системный промпт кэшируется на час (одинаковый у всех мастеров).
- У запросов к Sonnet 5.5 включён серверный запасной вариант (`fallbacks: "default"`): если классификатор безопасности откажет, сервер сам повторит на запасной модели.
- История диалога только дописывается: блоки размышлений модели передаются обратно как есть.
- Каждый запрос пишется в журнал (`LLM.log`): модель, токены, кэш, стоимость, результат проверки.

## Запуск

```bash
uv sync && uv run pytest                                  # логика на подставном клиенте, без затрат
export ANTHROPIC_API_KEY=...                              # для живых запросов (стоят денег)
uv run mebel-ai design "шкаф-купе 2,4 метра, три двери, зеркало посередине"
uv run python evals/run.py                                # оценка на наборе примеров
```
