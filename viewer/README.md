# viewer — общая 3D-сцена

Пакет `@mebel/viewer`: из viewer model ядра (`core/src/mebel_core/viewer.py`, формат `"1"`) строит сцену three.js. Нужен ссылке клиента (`web/`, Next.js 15) и приложению мастера (`app/`, Expo SDK 58). Оба на React 19, `@react-three/fiber` 9, drei 10 (peer-зависимости: `react >=19`, R3F `>=9 <10`, drei `>=10 <11`, three `>=0.160 <0.180`).

Четыре точки входа:

| Импорт | Что внутри | Зависимости |
| --- | --- | --- |
| `@mebel/viewer` | Ядро без React и DOM: `ProductScene`, оси, геометрия, UV, материалы, размеры, качество, `fitCamera`, `parseViewerModel` | `three` |
| `@mebel/viewer/react` | `ProductObject` (внутри любого `<Canvas>`, подходит и для `@react-three/fiber/native`) и `ProductViewer` (готовый просмотр для веба: Canvas, OrbitControls, свет, тень, автокадр) | `react`, `@react-three/fiber`, `@react-three/drei` |
| `@mebel/viewer/export` | `exportGlb(model, 'closed' \| 'open')`, `exportGlbVariants(model)`: GLB в метрах | `three` (GLTFExporter); работает в браузере и в Node |
| `@mebel/viewer/thumbnail` | Превью для карточек: `renderThumbnail` (браузер), `thumbnailScene` / `renderThumbnailWith` (expo-gl), `thumbnailPng` (Node, без WebGL) | `three` |

## Как устроено

- Оси: three.x = X, three.y = Z, three.z = −Y. Фасад смотрит в +z, фасады (Y < 0) стоят в z > 0.
- Единицы: по умолчанию метры (`units: 'm'`), как в AR. Для тестов есть `units: 'mm'`.
- Деталь — плита `length × width × thickness`. Размещение «запекается» в геометрию: в GLB/USDZ нет зеркальных матриц. Если оси u, v, n образуют левую тройку, порядок обхода граней разворачивается, и нормали смотрят наружу.
- Контур (`contour`): линии и дуги выдавливаются на толщину. `clockwise: true` значит, что угол убывает в локальной плоскости (x — длина, y — ширина).
- Контур и вырезы (`cutouts`): вырезы становятся дырками в выдавленной плите (мойка, варочная панель).
- Материалы: по типу поверхности и качеству (см. ниже). Карта окружения — процедурная «комната» (RoomEnvironment), не HDRI-файл. Рёбра рисуются тонкими тёмными линиями и не участвуют в выборе детали.
- Узлы: у каждого узла своя группа `node:<id>` с точкой в `origin`. Для rotate/lift — поворот на `range`° вокруг `axis` по правилу правой руки в осях ядра. Для slide/sliding_door — сдвиг на `range` мм вдоль `axis`.
- API сцены: `openNode / closeNode / toggleNode / openAll / closeAll` (плавно, через `update(dt)`); `setNodeOpen(id, t)` и `setAllOpen(t)` (сразу); `explode(on)` и `setExplode(t)`; `pick(raycaster)` и `pickAt(camera, ndcX, ndcY)` → `{ kind, number, key, name, role, node, point, distance, hardware? }`; `currentBounds()`, `closedBounds`, `stats()`, `dispose()`; плюс размеры, подсветка и кадр (ниже).

```tsx
import { ProductViewer, type ProductHandle } from '@mebel/viewer/react';
const ref = useRef<ProductHandle>(null);
<ProductViewer ref={ref} model={viewerModel} onPartTap={(p) => console.log(p.number, p.key)} />
// ref.current?.openAll(); ref.current?.explode(true);
```

## Фурнитура (ручки, петли, штанга, ножки…)

Ядро кладёт в viewer model поле `hardware` (и палитру `hardwareFinishes`) — см. `core/src/mebel_core/hw3d.py`. Это только картинка: детали, раскрой и смета не меняются, фурнитура уже посчитана в смете. Всё выводится из модели деталей — ручки и чашки петель стоят ровно по присадке (отверстия «ручка» и «чашка петли»), ряды угловой кухни учитываются сами. Тот же список рисует серверный GLB (`core/glb.py`, узлы `hw:<id>`), так что AR и ссылка клиента показывают то же.

| kind | Что | Где | Двигается с |
| --- | --- | --- | --- |
| `handle` | скоба (две стойки + ручка Ø12, вынос 30 мм), сталь | по отверстиям присадки: дверь — вертикально у края открывания; низкий фасад (нижние кухни, тумба) — у верха, высоко висящий (верхние, антресоль) — у низа, высокая дверь — ~1 м от пола; ящик — горизонтально по центру, ближе к верху | дверью / ящиком |
| `hinge` | чашка Ø35 с накладкой (на двери) + плечо и планка (на корпусе), сталь | по чашкам присадки | чашка — с дверью, плечо — на месте |
| `rod_holder` | фланец на боковине + чашка вокруг штанги, хром | концы штанги (сама штанга — деталь `role: 'rod'`, рисуется овальной трубой) | — |
| `slide` | шариковые: шина на ящике + шина на корпусе; скрытые: шина под ящиком; сталь | по боковинам ящика, на высоте присадки | внутренняя шина — с ящиком |
| `leg` | кухонная ножка: пята, стойка, площадка, чёрный пластик | под дном нижних модулей кухни, 4 шт. (крыло углового — 2) | — |
| `profile`, `rail` | алюминиевые профили двери-купе (вертикальные — они же ручки) и рельсы | по заполнениям купе | профиль — с дверью |
| `carousel`, `swing_shelf` | карусель 3/4 (две полки с бортиком на штанге, вырез — к дверям) и поворотная полка | угловой модуль кухни (`corner_fill`) | — |

Ручки по схеме (`handles.kind`): `bar` — скоба, `knob` — кнопка, `gola` — профиль, `none` — без ручек. `knob`: ядро шлёт два цилиндра (ножка и шляпка) — вьюер рисует тело вращения (розетка, тонкая ножка, скруглённая шляпка-грибок). `gola`: ядро шлёт бокс за фасадом — вьюер рисует алюминиевый C-профиль (полка во всю глубину, задняя стенка, короткая верхняя губа; канал открыт к фасаду), он на корпусе (`node: null`) и не едет с фасадом. Отделки: `steel, chrome, nickel, zinc, alu, plastic_*`, `brass` (латунь — тёплая, шлифованная), `gold` (золото — яркое, полированное), `black`.

**«Взрыв»:** фурнитура разлетается вместе со своей деталью-«родителем» (`part`): ручка — с дверью, ножка — с дном, штангодержатель — со штангой. **Качество:** `low` рисует только видную фурнитуру (без петель и направляющих), опция `hardware: false | 'visible' | 'all'` важнее пресета; при слиянии (low/medium) фурнитура сливается по отделке: у двери или ящика — один меш (петли, направляющие и ручки — одна отделка «сталь»). Цена: wardrobe_full medium 48 → 63 вызова, low 24 → 36; kitchen_straight medium 42 → 56, low 21 → 34. Металл без карты окружения рисуется «полуметаллом» (иначе он чёрный), с картой — полным металлом.

### Контракт userData (выбор касанием)

| Меш | userData |
| --- | --- |
| деталь (с декором — пазы, накладки и вставки внутри этого же меша) | `kind: 'part'`, `partNumber`, `partKey`, `nodeId`; у фасада со вставкой ещё `inlay: { name, finish, triStart, triEnd }` |
| фурнитура | `kind: 'hardware'`, `hardwareId`, `hardwareKind`, `hardwareName` (как в смете: «Ручка-скоба 128 мм»), `partKey` (деталь-«родитель»), `nodeId` |
| LED-профиль | `kind: 'light'`, `lightId`, `partKey` — луч его не видит; пятна света — `isLedGlow: true`, луч не видит |
| комната | `kind: 'room'`, `isRoom: true` — луч не видит |
| тени у стыков (AO) | `kind: 'ao'`, `isAo: true` — луч не видит |
| общий меш слияния | `isMerged: true` — луч его не видит |
| рёбра | `isEdges: true` — луч их не видит |

`pick()` / `pickAt()` / `ProductObject.onPartTap` при попадании в фурнитуру возвращают **деталь-«родителя»** (`number`, `key`, `node` — поэтому тап по ручке открывает дверь) плюс `kind: 'hardware'` и `hardware: { id, kind, name }`; при попадании в металлическую вставку или кант — фасад и `kind: 'decor'`, `decor: { kind: 'inlay', name: 'Вставка (латунь)' | 'Кант (золото)' …, finish }` (определяется по `faceIndex` попадания; в `pickFromObject(obj, point, distance, faceIndex)` передайте его, R3F даёт `e.faceIndex`); в паз фрезеровки или накладку — это сам фасад, `kind: 'part'`. `scene.decor` — список вставок (`DecorHandle`: `part`, `finish`, `name`, диапазон треугольников). `scene.hardware` — список `HardwareHandle` (`item`, `mesh`, `parent`), `scene.hardwareFor(target)` — фурнитура по id или префиксу; `highlight('sections[0].doors.door[1]')` подсвечивает и дверь, и её ручку.

## Декор фасадов (docs/decor_contract.md)

Ядро кладёт в деталь `decor`: `paint`, `milling[]`, `overlay[]`, `inlay[]`, `radius`, `face` (лицевая — локальная z = 0, наружу z < 0). Путь — сегменты как у контура; первый может быть `{kind: 'move'}` (так шлёт ядро), иначе начало — `start` или, у замкнутого пути, конец последнего сегмента (оба вида понимаются, `strokePolyline`).

| Что | Как рисуется | Цена |
| --- | --- | --- |
| `paint` | материал `paint:<цвет>:<блеск>`: цвет вместо текстуры декора; matte → roughness 0.8, satin 0.45 (лёгкий clearcoat на high), gloss 0.15 (clearcoat 1 на high; на medium — отражения «студии») | 0 вызовов |
| `milling` | без CSG: полоса чуть перед лицом фасада, стенки паза с нормалями к центру (одна светлее, другая в тени) и тёмное дно — цвет вершин | 0 вызовов — в меше фасада |
| `overlay` | настоящий профиль, выдавленный по пути: `flat` — с фасками, `round` — полукруг; тот же материал/краска | 0 вызовов |
| `inlay` | выпуклая полоса с «бликующими» нормалями + тёмный шов под ней; металл — атрибут `metalMask`: шейдер подменяет цвет/металличность/шероховатость отделки (brass, gold, black, chrome) | 0 вызовов |
| `radius` | скруглённый контур детали, если ядро не прислало `contour` | — |

Всё лежит в меше самой детали (материал с `vertexColors`, атрибуты `color`, `metalMask`, `decorLift`), поэтому декор едет с дверью, разлетается при «взрыве», подсвечивается и сливается при low/medium вместе с фасадом. Рёбра строятся только по самой детали. Пазы и вставки лежат в 0,2–0,6 мм от лица: им дан сдвиг глубины в шейдере (`decorLift`, `DECOR_DEPTH_BIAS`), чтобы не мерцали на телефоне.

**Металл без карты окружения.** Приложение (expo-gl) не делает PMREM, поэтому раньше металл был «полуметаллом». Теперь сцена сама ставит маленькую «студию» (`createStudioEnvironment`: атлас CubeUV 336×128 RGBA8, считается на CPU, three берёт его без PMREM) всем отражающим материалам — металл фурнитуры и вставок, зеркало, глянец, полуматовая краска — пока снаружи не задана своя карта (`setEnvironment`). На low (Lambert) её нет. Выключить: `studioEnvironment: false`.

## LED-подсветка (`lights[]`)

`{ id, zone, from, to (мм), temp, nodeId, part, mount, profile: {width, height} }`. Рисуется: алюминиевый профиль с молочным рассеивателем (в пазу — заподлицо, `mount: 'surface'` — накладной короб), один меш на отрезок (MeshBasic, цвет вершин). При включении: рассеиватель светится цветом температуры (3000 K тёплый, 4000 K нейтральный, 6000 K холодный), «пятна» — прямоугольники с градиентной текстурой и аддитивным смешением: на поверхности под профилем (луч вниз до полки/столешницы, пятно обрезается по детали), заливка задней стенки ниши (от профиля вниз) и ореол вокруг рассеивателя — один меш на отрезок; плюс одна `PointLight` на отрезок (не больше 4) — подсвечивает стенки ниши. Свет с `nodeId` едет с узлом, профиль разлетается при «взрыве» со своей деталью `part`, пятна при «взрыве» прячутся.

`scene.setLightsOn(on, { dim? })`, `toggleLights()`, `lightsOn`, `hasLights`; React: проп `lightsOn` у `ProductObject`/`ProductViewer`, `ref.current.setLightsOn(on)`. Включение — «вечер»: свет сцены, не принадлежащий изделию (hemisphere, directional, ambient), умножается на `dim` (0.4), фон сцены (`scene.background`, если это цвет) темнеет; выключение и `dispose()` возвращают всё как было. Прозрачный канвас (фон экрана под ним) вьюер не трогает — затемнить фон экрана должен сам экран.

## Комната (встроенная мебель, `room`)

`room: { walls: [{ id, kind: 'wall_left'|'wall_right'|'wall_back'|'ceiling'|'floor', min, max }], colors?: { wall, floor, ceiling? } }` — боксы в мм, оси изделия. Рисуется одним матовым мешем (Lambert, цвет вершин): от каждого бокса — только грань, обращённая к изделию, `FrontSide`. Поэтому стена, за которой оказалась камера (смотрим сбоку, сверху), отсекается сама и никогда не закрывает мебель, а видимые стены и пол непрозрачные. Цвета — из `colors` (потолок — светлее стен), без них — светло-серые. Не выбирается лучом, не разлетается, не входит в `closedBounds`/`currentBounds` (кадр — по изделию), не попадает в GLB (`exportGlb`) и превью. `scene.setRoomVisible(on)`, `roomVisible`, опция `room: false`; React: проп `roomVisible`, `ref.current.setRoomVisible(on)`.

## Размеры (FR-19, кнопка «Размеры»)

`scene.showDimensions(true)` / `toggleDimensions()` / `dimensionsVisible`. Рисуются габарит (ширина сверху, высота справа, глубина справа на полу) и ширины секций «в свету». Секции — промежутки между стойками `side` / `partition` на одной высоте; касающиеся боковины соседних модулей считаются одной стойкой. Ряды считаются отдельно: у кухни — нижние и верхние модули. Значения без сцены: `computeDimensions(model)` → `{ overall, rows: [{ zMin, zMax, sections: [{ x0, x1, width }] }] }`.

Цифры — штриховой шрифт из полос (без canvas и шрифтов), поэтому работают и в вебе, и в `@react-three/fiber/native`. Подписи поворачиваются к камере. Свою подпись (canvas-спрайт, drei `<Text>`) можно передать через `dimensions: { labelFactory }`.

## Качество (`quality: 'low' | 'medium' | 'high'`)

| | high (по умолч.) | medium | low |
| --- | --- | --- | --- |
| Рёбра | да | да (слиты) | нет |
| Тень на полу | каждый кадр | один раз | нет |
| Отражения окружения | всем | металл, зеркало, глянец, акрил | нет |
| dpr не больше | 2 | 1.5 | 1 |
| Материалы | Physical (лак, soft-touch) | Standard | Lambert |
| Слияние мешей | нет | да | да |
| Тени у стыков (AO) | да | да | да |

Слияние: детали одного материала сливаются в один меш. Неподвижные — в общий меш в `root`, детали узла — в общий меш внутри группы `node:<id>`, так что двери и ящики двигаются отдельно. Меши отдельных деталей остаются скрытыми: по ним работают выбор лучом, габариты, подсветка и «взрыв» (во время «взрыва» показываются отдельные детали). Явные опции (`edges`, `merge`, `textures`, `curveSegments`) важнее пресета. `detectQuality()` — грубая догадка по устройству; `ProductViewer quality="auto"`.

Замер: `npm run bench` (сборка и `scripts/bench.mjs`). Draw calls в закрытом виде (без размеров):

| | high | medium | low |
| --- | --- | --- | --- |
| kitchen_straight (85 деталей) | 170 (≈342 за кадр с тенью) | 42 | 21 |
| wardrobe_full (60 деталей) | 120 (≈242) | 48 | 24 |

Треугольников везде ~1 000: упираемся не в них. Размеры добавляют один вызов на подпись и один на все линии.

Декор и подсветка (medium, закрыто; «без декора» — та же модель без `decor` и `lights`): wardrobe_decor 48 → 51 (+6 %, это 3 LED-профиля; сам декор — 0), со включённым светом 54 (+12,5 %); kitchen_decor 54 → 57 (+5,5 %), со светом 60 (+11 %). Треугольники: wardrobe_decor 8,8 → 9,3 тыс., kitchen_decor 6,2 → 7,6 тыс.

## Материалы и текстуры

Тип поверхности по PRD: `matte | gloss | softtouch | veneer | acrylic | mirror | metal` (+ `glass`). Пока в каталоге нет поля «тип», он угадывается по id (`materialType`): `mirror_*` — зеркало, `rod_*` / chrome / alu — металл, `countertop_*` и gloss — глянец, acryl — акрил, soft — soft-touch, veneer / shpon — шпон, остальное — матовый. Явно: `options.materials = { ldsp_18_oak: { type: 'veneer', map: 'https://…/oak.jpg', tileMm: [2800, 2070], grainAxis: 'u' } }`.

UV строятся для каждой детали в локальных мм по `grain`: `length` — волокна вдоль длины (локальная x), `width` — вдоль ширины (y), `none` — без поворота (на всех гранях, включая кромки, — плоская проекция по оси грани, без растяжения и диагоналей). Единица UV — 1000 мм; реальный размер плитки задаёт повтор текстуры (`repeat`), так что одна картинка на GPU обслуживает все детали.

Сканы декоров: если в модели у материала есть `texture` (URL, `/static/…`, `bundled:<имя>`) и `textureSizeMm` (EMAN: дерево ≈ 1000 × 300 мм, остальное ≈ 600 × 600; волокна на картинке — по горизонтали), сцена грузит его через `options.loadTexture(url) → Promise<Texture | null>` (в браузере по умолчанию TextureLoader; в приложении — `app/src/three/textures.ts`, expo-asset + `{ localUri }` для expo-gl) и ставит во все материалы этого декора (скан не тонируется цветом). Пока скан грузится или если не загрузился — у `hasGrain` и шпона процедурные волокна в реальном масштабе (плитка `GRAIN_TILE_MM` = 800 × 200 мм: годичные слои ≈ 3,5 мм, поры-штрихи, мягкий изгиб и полосы тона 100–300 мм). Догрузка скана вызывает `scene.onChange` (перерисовать кадр при `frameloop="demand"`).

## Тени у стыков (AO)

Ниша не «дырка»: у стыков неподвижных деталей (полка — задняя стенка, полка — боковина, стойка — дно, столешница над боковиной) лежат полосы-градиенты (`contactShadowGeometry`: чёрный + альфа в цвете вершин, ширина 64 мм, сила 0.3, профиль ≈ exp). Один меш `scene.ao`, MeshBasic, прозрачный, без записи глубины, 2 мм над гранью + polygonOffset. Прячется при «взрыве» и «рентгене»; двери и ящики не участвуют. Цена: +1 вызов, +0,7–2 тыс. треугольников (wardrobe_full medium 63 → 64 вызова, 5,5 → 6,6 тыс.; kitchen_straight 56 → 57, 8,4 → 10,4 тыс.), построение < 1 мс. Выключить: `ao: false` (GLB и программное превью строятся без AO).

## Камера-штатив и размеры поверх 3D (`ViewRig`, `dimensionAnchors`)

`new ViewRig({ fov: 28, padding: 28 })` — камера без React: `setViewport(w, h)` (px канваса), `setInsets({ top, right, bottom, left })` (сколько закрыто плашками), `setContent(bounds, margins?)` (габарит и поля под размеры, `DIMENSION_MARGINS`), `fit({ animate })` — изделие вписывается в свободную область с отступом `padding` от каждой плашки, центр проекции сдвинут (`setViewOffset`) в центр этой области, поэтому при вращении модель не уезжает под интерфейс. Перспектива FOV 28° (без «широкоугольного» расширения низа); `setProjection('orthographic')` — плавный «долли-зум» (FOV → 4°, камера отъезжает), затем ортогональная камера (`rig.camera` меняется). `focusDimension('width' | 'height' | 'depth' | null)`: ширина/высота — строго спереди, глубина — сбоку в ¾, всё в ортогонали; `null` — назад к прежнему виду. `orbit(dθ, dφ)`, `zoomTo(span)`, `update(dt)` каждый кадр (true — ещё движется), `onChange` после каждого изменения. near/far перспективы меняются ступенями (×2), не каждый кадр.

`rig.anchors()` / `dimensionAnchors(bounds, project, viewDir)` — экранные точки (px, y вниз) для оверлея: на каждый размер `{ visible, a, b (размерная линия), edgeA, edgeB (мерное ребро), ext (выносные), ticks (засечки 45°), label (центр плашки), normal, angle, length }`. Ширина — над силуэтом, высота — справа (плашка правее линии), глубина — по левому ребру вглубь, на силуэте (камера справа сверху — верхнее, слева — нижнее ребро видимой боковины), плашка слева от изделия (`labelOffset: 'end'`); спереди глубина «в точку» — `visible: false` (кроме вводимой). `DIMENSION_MARGINS` симметричные (76 по бокам, 38 сверху/снизу) — изделие по центру свободной области. В приложении линии рисует `ProductCanvas` (RN-вью 1 pt — чётко на любом экране).

Размеры детали «на ней самой»: `scene.partBox(номер | ключ)` → 8 углов коробки детали в сцене в текущем положении (бит 0 индекса — длина, 1 — ширина, 2 — толщина, по её осям) и `size` (L × W × T, мм). `rig.focusPart(corners | null, { animate, turn })` — камера на деталь: вид доворачивается ровно настолько, чтобы были видны плоскость и толщина (`partViewAngles`), деталь вписывается в свободную область с полями `PART_MARGINS`; `null` — назад к виду до фокуса. `rig.setPartCorners(corners)` — деталь едет (дверь, «взрыв»), `rig.partAnchors()` / `partAnchors(corners, project)` — точки для длины, ширины и толщины (ребро силуэта по каждой оси, плашка рядом с линией). В приложении — `ProductCanvas` с `selectedPart` + `partDimensions`.

## Подсветка и кадр (SCR-25, «элемент подсвечен в 3D»)

`scene.highlight(target, { ghost?, color? })`, где `target` — номер детали, ключ, префикс ключа (`'sections[1]'`, `'base[2]'`), id узла или список. `ghost: true` делает остальное полупрозрачным: видно полку за закрытой дверью. `clearHighlight()`, `highlighted`, `boundsOf(target)`, `frameTarget(target, fov, aspect, direction?)` → `CameraFit`. В React: `ref.current.highlight(...)`, `ref.current.focus(target)` (плавный перелёт камеры) или пропсы `highlight`, `ghost`, `focusOnHighlight`, `dimensions`.

```tsx
<ProductViewer ref={ref} model={m} quality="auto" dimensions={showDims} highlight={aiPartKey} ghost focusOnHighlight />
```

## Превью для карточек (SCR-03)

- Браузер: `const png = await renderThumbnail(model, { width: 512, height: 384, background: 'white' })` → Blob (вид 3/4; `'transparent'` по умолчанию). Свой WebGL-контекст вне экрана создаётся и сразу освобождается. Для пачки карточек передайте общий `renderer`.
- Приложение (expo-gl):
  ```ts
  const gl = await GLView.createContextAsync();
  const renderer = new Renderer({ gl }); // expo-three
  renderThumbnailWith(renderer, model, { width: gl.drawingBufferWidth, height: gl.drawingBufferHeight, background: 'white' });
  gl.endFrameEXP();
  const snap = await GLView.takeSnapshotAsync(gl, { format: 'png' }); // snap.uri
  ```
- Node (сервер): настоящего WebGL нет (headless-gl даёт только WebGL1, а three ≥ 0.163 работает только с WebGL2). Поэтому `thumbnailPng(model, { deflate: (d) => zlib.deflateSync(d) })` растеризует программно (z-буфер, плоская заливка, контуры, сглаживание 3×3): ~100 мс, ~10–15 КБ. Без текстур и бликов, но для карточки хватает.

## Известные пробелы

- Отверстия (`holes`) не рисуются (по ним стоит фурнитура). Вложенные узлы (дверь внутри ящика) не рисуются: в контракте нет родителя узла.
- Тип поверхности угадывается по id материала, пока в каталоге ядра нет поля. Сканы декоров грузятся, только если в модели есть `texture` и передан `loadTexture`.
- HDRI-файла нет, отражения идут от процедурной комнаты (веб) или своей «студии» (приложение).
- Фрезеровка — не настоящая выемка: при взгляде вплотную под острым углом видно, что паз плоский. Пересекающиеся пути (ромбы встык) рисуются наложением. На одном фасаде — одна отделка вставок (берётся первая).
- Пятна LED обрезаются по габариту одной детали (полки/столешницы) и считаются один раз в закрытом виде; если под профилем открыть ящик, пятно останется на месте.
- Draw calls посчитаны по сцене, а не на телефоне. FPS на бюджетном Android и iPhone надо замерить на устройствах (NFR-04).
- Размеры не прячутся при «взрыве» и открытых дверях: это решает экран.
- Превью в Node без текстур, бликов и теней.
- GLB строится этим же кодом только как запасной вариант. Основные GLB делает сервер ядра (`schemas/samples/*.glb`).
